Git Workflow Practice
====================

1. Install and configure Git

sudo apt update
sudo apt install git
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main

2. Create a repository and make the first commit

mkdir git-practice
cd git-practice
git init
echo "# Git Practice" > README.md
git add README.md
git commit -m "docs: add readme"

3. Create a feature branch and merge it

git switch -c feature/add-notes
echo "My first Git workflow exercise." > notes.txt
git add notes.txt
git commit -m "feat: add practice notes"

git switch main
git merge --no-ff feature/add-notes
git log --oneline --graph --all

Useful inspection commands:

git status
git diff
git diff --staged
git branch
git log --oneline --graph --all

4. Practice resolving a conflict

Create a branch and change one line in README.md, then commit:

git switch -c feature/change-title
# Edit README.md
git add README.md
git commit -m "docs: update title"

Switch to main, change the same line differently, and commit:

git switch main
# Edit the same line in README.md differently
git add README.md
git commit -m "docs: revise title"
git merge feature/change-title

Edit README.md to resolve the conflict, then finish the merge:

git add README.md
git commit

5. Practice remote collaboration

Create an empty repository on GitHub or GitLab, then use its URL below:

git remote add origin <repository-url>
git push -u origin main

Create and push a feature branch:

git switch -c feature/something
# Make a change
git add <file>
git commit -m "feat: describe the change"
git push -u origin feature/something

Open a Pull Request or Merge Request in the web interface, review the changes,
and merge it. Then update your local main branch:

git switch main
git pull

# 本地解决该 PR 冲突完整步骤（对应截图：`gitworkflow.txt` 文件冲突）

> 
> 面试英文回答 + 实操命令，适配奇石乐面试。
> 场景：你的 feature 分支提交 PR，提示`This branch has conflicts that must be resolved`，冲突文件`gitworkflow.txt`，**不用网页编辑器，本地命令行处理**

## 完整操作流程（命令）

```
#1. 拉取远程最新信息
git fetch origin

#2. 切换到你当前这个PR对应的本地功能分支
git checkout feature/testpr3

#3. 方式A：把main合并进当前分支（merge方式，面试常讲）
git merge origin/main
```

此时 git 检测到`gitworkflow.txt`冲突，命令行提示冲突，流程暂停。

```
#4. 打开冲突文件 gitworkflow.txt，IDE里手动处理冲突标记
# <<<<<<< HEAD       本地分支（你的代码）
# ...你的修改
# =======
# ...main分支上别人提交的修改
# >>>>>>> origin/main

#5. 编辑完成，保存文件，标记冲突已解决
git add gitworkflow.txt

#6. 完成本次merge提交
git commit
```

```
#7. 推送到远程，PR页面自动刷新，冲突提示消失
git push origin feature/testpr3
```

> 
> 备选方式 B（rebase，很多外企团队偏好线性历史）

```
git checkout feature/testpr3
git rebase origin/main
# 遇到冲突，修改文件 -> git add 文件
git rebase --continue
# 全部完成后推送
git push origin feature/testpr3
```

> 
> ⚠️注意：rebase 改写历史，若远程分支已经被别人使用，push 时可能需要`--force-with-lease`，**团队共享分支慎用**。
